Remote sessions with Tailscale

SuperDAW connects peers directly, which needs everyone on one network. Tailscale builds that network across the internet — so a collaborator three time zones away joins exactly like someone in the next room.

Why this is needed

LAN means local network — for now.

SuperDAW's session host listens on its own address and peers connect straight to it. No server sits in the middle, which is why latency is as low as it is. It also means the two machines have to be able to see each other, and two houses on two different internet connections cannot.

A mesh VPN solves exactly this. It gives every one of your machines an address on one private virtual network, and they reach each other over that network no matter whose Wi-Fi they are actually on. SuperDAW does not need to know it is happening — it just sees two machines that can reach each other.

If you are all in the same building, you can close this page. A studio, a rehearsal room, a house, one venue's Wi-Fi — anywhere the machines already share a network, SuperDAW sessions work on their own with nothing installed and no account anywhere. Tailscale is only for the case where the network does not already exist.

Before you start

What this costs and what you need.

  • Free, for this use Tailscale's Personal plan is free forever and covers up to 6 users with unlimited personal devices — far more than a session needs. It is for non-commercial use.
  • Both people install it Tailscale has to run on every machine in the session. There is no way for one person to cover for everyone.
  • Both people sign in somewhere Tailscale authenticates through an existing account — Google, Microsoft, GitHub, Apple and others. There is no separate password to invent.
  • Roughly ten minutes, once After the first setup, later sessions are just "start Tailscale, start SuperDAW".

A note on what you are trusting. Tailscale is a third party and a separate company from SuperDAW — it needs an account, which is exactly the thing SuperDAW itself avoids. Traffic between peers is end-to-end encrypted and Tailscale cannot read your project, but the tradeoff is real and it is the reason this is a stopgap rather than the plan. Native relay support is being built so this page eventually becomes unnecessary.

Part 1 · Both of you

Install Tailscale and sign in.

Everyone in the session does this on their own machine, including the host.

  1. Download it from tailscale.com/download. There are builds for Windows, macOS, Linux, iOS and Android. On Windows you get an installer; run it and let it install the network adapter it asks about — that adapter is the whole mechanism.
  2. Sign in when it opens. Pick any provider you already have an account with. Both of you should sign in the same way if you plan to share a tailnet — see Part 2.
  3. Confirm it is connected. On Windows, Tailscale lives in the system tray (the arrow near the clock); the menu should say Connected. Installed but signed out is not enough, and it is the single most common reason this does not work — see the troubleshooting note below.
  4. Find your Tailscale address. It always starts with 100. — that range is reserved for exactly this. Three ways to see it: the tray menu shows it under your machine name; the admin console lists it on the Machines page; or run tailscale ip -4 in a terminal. 
# Windows PowerShell, macOS or Linux terminal
tailscale ip -4
# → 100.92.14.37

# everything Tailscale currently sees
tailscale status

Part 2 · Connecting the other person

Two ways, and they are not equivalent.

Installing Tailscale separately is not enough — two strangers' Tailscale networks cannot see each other by default. You have to deliberately connect them, and there are two mechanisms. Pick one.

Recommended for a band

Invite them into your network

They become a member of your tailnet. Both machines see each other fully, in both directions, with nothing else to configure. Simplest to reason about, and the right answer for people you record with regularly.

Costs one of your 6 free user seats, and they can reach anything your access rules allow — so use it for people you'd trust on your home network.

Recommended for a one-off

Share just the one machine

They stay in their own tailnet and receive access to exactly one machine — yours. Nothing else of yours is visible, and it does not consume a user seat.

Requires that they already have their own Tailscale account, and adds one direction-of-traffic caveat that matters here. Read the quarantine note below.

Route A — invite them into your tailnet

  1. Open the Users page of the Tailscale admin console. You need to be the Owner or an Admin of your tailnet, which you are by default if you created it.
  2. Select Invite external users, and enter their email address. There is also an option to generate a plain invite link if you'd rather send it yourself over chat.
  3. They open the link and authenticate with their own SSO provider. Once they do, they appear on your Users page and their devices join your tailnet.
  4. Check they can see the host. On their machine, tailscale status should now list your machine and its 100.x address.

Route B — share only the host machine

  1. Open the Machines page of the admin console and find the machine that will host the session. This matters — share the host, not the guest's machine.
  2. Open that machine's ⋯ menu and choose Share.
  3. Use Share by email to send an invitation, or Copy invite link to send it yourself. A link is single-use unless you toggle Reusable link. Unused invite links expire after 30 days.
  4. They accept the invite. They must be the Owner or an Admin of their own tailnet — in practice, they need to have signed up for Tailscale themselves first. The shared machine then appears in their machine list.

The quarantine rule, and why Route B still works. Tailscale quarantines shared machines by default: a shared machine can answer incoming connections from the person you shared it with, but cannot start connections into their network.

That is precisely the shape of a SuperDAW session — the host listens, and peers dial in — so sharing the host's machine works. Sharing the guest's machine instead would not. If you ever need traffic both ways, Tailscale supports mutually sharing a machine from each side.

Part 3 · The session

Start SuperDAW exactly as you normally would.

There is no Tailscale setting inside SuperDAW, and nothing to paste. It detects the Tailscale adapter on its own.

  1. Check Tailscale is connected on both machines before opening SuperDAW. This is the step people skip.
  2. The host clicks Collab → Start. SuperDAW builds a join code from its own address, and when a Tailscale adapter is present and carrying an address, it picks that one over your ordinary Wi-Fi address automatically.
  3. Send the join code. It looks like CHE0W-9E276-JF5J0 — fifteen characters in three groups. It is case-insensitive and deliberately avoids ambiguous letters, so it survives being read aloud over a call.
  4. They paste it into the launcher and join. The project streams over, assets transfer in the background, and you are both editing.

If Tailscale is installed but not connected, this fails quietly. A disconnected Tailscale adapter still exists, holding a self-assigned 169.254.x.x address that routes nowhere. SuperDAW deliberately skips those and falls back to your ordinary LAN address — so you get a join code that looks perfectly valid, and simply cannot be reached from outside your house.

The tell is the address inside the code: a working remote session encodes a 100.x host. If your collaborator's join attempt just hangs, check the tray first.

When it doesn't work

Troubleshooting, in order.

  • Is Tailscale actually connected? On both machines. Check the tray, or run tailscale status. Ninety percent of failures stop here.
  • Can the guest see the host at all? Run tailscale ping <host-machine-name> from the guest. If that fails, the problem is the Tailscale link, not SuperDAW — nothing in the DAW will fix it.
  • Did you share the right machine? On Route B, the host's machine is the one that must be shared. Sharing the guest's machine leaves the connection pointing the wrong way through quarantine.
  • Is the code encoding a 100.x address? If the host had Tailscale down when the session started, it encoded the wrong address. Stop the session, connect Tailscale, and start it again to mint a fresh code.
  • Firewall prompt still waiting? Windows may ask whether to allow SuperDAW on the network the first time you host. If it was dismissed, allow it in Windows Defender Firewall and restart the session.
  • Still stuck? Open an issue with what tailscale status prints on both ends. Remote-session reports are genuinely useful — they are the hardest thing to test alone.

The honest summary

This is a workaround.

It works, it is fast, and it is genuinely peer-to-peer. It is also three things SuperDAW is otherwise designed to avoid.

Another program to install

One more dependency, one more thing that can break, on every machine in the session.

It requires accounts

Everyone signs in somewhere. SuperDAW's entire point is that it asks you for nothing.

It is a lot to explain

Most musicians want to paste a code and play — not read a page about mesh VPNs.

Native relay support — remote sessions with no VPN and no extra account — is being built. Until it ships, this gets you the real thing today.
