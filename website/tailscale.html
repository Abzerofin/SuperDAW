Remote sessions with Tailscale

SuperDAW connects people directly, which means everyone has to be on one network. Tailscale builds that network across the internet, so someone three time zones away joins the same way as someone in the next room.

Why you'd want this

LAN means local network.

The host listens on its own address and everyone else connects straight to it. Nothing sits in the middle, which is why it's as fast as it is. It also means the machines have to be able to see each other, and two houses on two different internet connections can't.

A mesh VPN fixes that. It gives all your machines an address on one private network, and they talk to each other over it no matter whose Wi-Fi they're actually sitting on. SuperDAW doesn't need to know any of this is going on. It just sees two machines that can reach each other.

If you're all in the same building, you can close this page. A studio, a rehearsal room, a house, one venue's Wi-Fi. Anywhere the machines already share a network, sessions work on their own with nothing installed and no account anywhere. Tailscale is only for when that network doesn't exist yet.

Before you start

What this costs and what you need.

  • Free for this The Personal plan is free with no time limit and covers 6 users and as many of your own devices as you like, which is well past what a session needs. It's meant for non-commercial use.
  • Everyone installs it It has to run on every machine in the session. One person can't set it up on behalf of everybody.
  • Everyone signs in somewhere Tailscale logs you in through an account you already have, like Google, Microsoft, GitHub or Apple. There's no new password to invent.
  • Ten minutes, once After the first time, starting a session is just "turn on Tailscale, open SuperDAW".

Worth being upfront about the tradeoff. Tailscale is a separate company, and it wants an account, which is the exact thing SuperDAW otherwise avoids. Traffic between machines is encrypted end to end and Tailscale can't read your project, but you're still bringing a third party into something that didn't have one. That's why I treat this as a stopgap rather than the plan, and why I'm working on a built-in relay so this page can eventually go away.

Part 1 · Everyone

Install Tailscale and sign in.

Everyone does this on their own machine, host included.

  1. Download it from tailscale.com/download. There are builds for Windows, macOS, Linux, iOS and Android. On Windows you get an installer. Run it and let it add the network adapter it asks about, because that adapter is the whole trick.
  2. Sign in when it opens, using whichever provider you already have an account with. If you're going to share one tailnet, it's worth both signing in the same way. Part 2 covers that.
  3. Check that it says Connected. On Windows it sits in the system tray, behind the little arrow near the clock. Installed but signed out isn't enough, and it's far and away the most common reason this doesn't work.
  4. Find your Tailscale address. It always starts with 100., since that range is set aside for this sort of thing. The tray menu shows it under your machine name, the Machines page in the admin console lists it, or you can run tailscale ip -4. 
# Windows PowerShell, macOS or Linux terminal
tailscale ip -4
# → 100.92.14.37

# everything Tailscale currently sees
tailscale status

Part 2 · Connecting the other person

Two ways to do it.

Both of you installing Tailscale isn't enough on its own. Two separate Tailscale networks can't see each other until you connect them, and there are two ways to do that. Pick whichever fits.

Good for a band

Invite them into your network

They join your tailnet as a member. Both machines can see each other properly, in both directions, and there's nothing else to set up. It's the easiest one to keep straight in your head, and the one to use for people you record with often.

It uses up one of your 6 free seats, and they'll be able to reach whatever your access rules allow, so treat it like letting someone onto your home network.

Good for a one-off

Share just the one machine

They stay in their own tailnet and get access to a single machine of yours. Nothing else you own is visible to them, and it doesn't use up a seat.

They'll need their own Tailscale account for this, and there's one catch about which direction traffic can flow. The quarantine note below explains it.

Route A — invite them into your tailnet

  1. Open the Users page in the Tailscale admin console. You need to be the Owner or an Admin, which you already are if you're the one who set the tailnet up.
  2. Hit Invite external users and put in their email address. You can also generate a plain link instead, if you'd rather send it over chat yourself.
  3. They open the link and sign in with their own provider. After that they show up on your Users page and their devices are part of your tailnet.
  4. Check they can see the host. Running tailscale status on their machine should now list yours, with a 100.x address next to it.

Route B — share only the host machine

  1. Open the Machines page and find the machine that's going to host the session. Which one you pick matters here. It has to be the host, not the guest's machine.
  2. Open that machine's ⋯ menu and choose Share.
  3. Share by email sends them an invitation, or Copy invite link gives you something to send yourself. Links only work once unless you turn on Reusable link, and an unused one expires after 30 days.
  4. They accept it. They have to be the Owner or an Admin of their own tailnet, which in practice means signing up for Tailscale first. Your machine then turns up in their machine list.

Why Route B needs the host shared, not the guest. Tailscale quarantines shared machines by default. A shared machine can answer connections coming from the person you shared it with, but it can't start one going the other way.

That happens to be exactly how a session works. The host sits there listening and everyone else dials in, so sharing the host is fine. Share the guest's machine by mistake and the traffic is pointing the wrong way through the quarantine. If you do need it working both ways, you can share a machine from each side.

Part 3 · The session

Start SuperDAW the way you normally would.

There's no Tailscale setting inside SuperDAW and nothing to paste anywhere. It finds the adapter by itself.

  1. Make sure Tailscale is connected on both machines before you open SuperDAW. This is the step everybody skips.
  2. The host clicks Collab → Start. The join code gets built from the host's own address, and if there's a Tailscale adapter sitting there with an address on it, that's the one it uses instead of your normal Wi-Fi address.
  3. Send the code over. It looks like CHE0W-9E276-JF5J0: fifteen characters in three groups. Case doesn't matter and the letters that look like each other are left out, so it survives being read down a phone.
  4. They paste it into the launcher. The project comes across, audio files follow in the background, and you're both working.

If Tailscale is installed but not connected, this fails quietly. The adapter is still there when it's disconnected, holding a self-assigned 169.254.x.x address that goes nowhere. SuperDAW skips those on purpose and falls back to your normal LAN address, so you end up with a join code that looks completely fine and can't be reached from outside your house.

The giveaway is the address buried in the code, which should be a 100.x one for a remote session. If someone's join attempt just sits there doing nothing, check the tray before anything else.

When it doesn't work

Troubleshooting, in order.

  • Is Tailscale actually connected? On both machines. Check the tray or run tailscale status. Most of the time it stops here.
  • Can the guest see the host at all? Run tailscale ping <host-machine-name> from their machine. If that doesn't work, it's the Tailscale link that's broken and nothing you do in the DAW will help.
  • Did you share the right machine? On Route B it has to be the host that's shared. Share the guest's machine and the traffic points the wrong way through the quarantine.
  • Does the code contain a 100.x address? If Tailscale was down on the host when the session started, the wrong address got baked in. Stop the session, get Tailscale connected, start it again for a fresh code.
  • Was there a firewall prompt? Windows asks whether to allow SuperDAW on the network the first time you host. If that got dismissed, allow it in Windows Defender Firewall and restart the session.
  • Still stuck? Open an issue and include what tailscale status says on both ends. Reports about remote sessions are worth a lot, since they're the hardest thing to test alone.

Being honest about it

This is a workaround.

It works, it's fast, and the connection really is direct. It's also three things SuperDAW otherwise goes out of its way to avoid.

Another program to install

One more thing to keep working, on every machine in the session.

It wants accounts

Everyone has to sign in somewhere, when the whole point is that SuperDAW asks you for nothing.

It's a lot to explain

Most people want to paste a code and start playing, not read a page about VPNs.

The built-in relay will make remote sessions work without a VPN or a second account. Until I've finished it, this gets you the real thing today.
